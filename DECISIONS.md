# Store Doctor — Architecture Decisions
r8 · Nov 18, 2026 · Overrides the private PRD (not in repo) on conflict. PRD synced to r8 on Nov 19.

## Principles
- Bit.ly-shaped: key = stan.store username, value = audit. Read-heavy by design; v1 target ~50 audits. Build the shape, not the scale.
- AP over CP: stale > error/spinner; reads never wait on writes. Exception: publish/unpublish/takedown (within CDN lag, #10).
- Published = pinned: a shared link → one audit forever, or 404.
- Two IDs: private `id` = sole access control, never public or shared; `public_id` = safe for URLs/metadata/images.

## Threat model
- Threat: a third party uses the tool to harass a specific creator, by notifying them, publishing a low score, or building a history of their store.
- Not a threat: agencies or peers auditing stores to give feedback or pitch services. Normal; matches existing SEO tools. Don't build per-auditor limits or login walls against it.
- Reasoning: screenshots mean any result can go public, so the goal isn't secrecy. The goal is adding no amplification: no tagging (#23), `noindex` + visitor label (#8), takedown (#19), short retention (#24).

## Decisions
1. Read path: Vercel CDN → Supabase Postgres. No Redis report cache.
2. Freshness: no auto re-audits (they change shared scores, let page views spend on the LLM). Report shows "audited X ago"; rate-limited Re-run for the private-link holder, disabled until the snapshot is 24 h old (#24).
3. Write path: one route `POST /api/audit`: fetch → parse → rules ∥ LLM → score → save; streams step events; `after()`/`waitUntil` finishes save on disconnect; `maxDuration` ≪ 2 min stuck threshold.
4. Inngest (`step.run` per stage): deferred until timeouts/failed saves are observed.
5. Dedupe: every request → own row, `id`, `public_id`. Share work, never IDs.
   - (a) Pending runner for same content → follower row (`source_audit_id` = runner), waits.
   - (b) Complete match on `snapshot_hash` + `rubric_version` + `model` → new complete row, `result` copied, `source_audit_id` = original.
   - Every audit (Re-run included) follows any pending runner for username (no fetch).
6. Data model: `result` immutable once complete; only mutable fields: `published_at`, and `snapshot.profile` (removed by purge, #24). One pending runner per (username, snapshot_hash) via partial unique index; followers exempt. Every status write is guarded `AND status='pending'` (runner save included), so a late save can't overwrite a sweep's `failed`.
7. Visibility: one field. Public ⇔ `published_at IS NOT NULL`; every read and write uses only that, plus a block-list check on public reads (no `visibility` column). Private by default; secret `/r/[id]` (`no-store`, `noindex`). Publish requires `status='complete'` → sets `published_at`, enables pinned `/report/[username]/[public_id]` (Share posts this; lookup by `public_id`, username must match). Unpublish clears `published_at` → 404. No bare `/report/[username]` in v1.
8. Third-party reports: `/report/*` `noindex`; label "generated by a visitor, not the store owner"; footer takedown contact → #18. `blocked_usernames` checked by audit + publish routes and public reads.
9. Cache tags: `report:{public_id}`, `user:{username}`. Publish and unpublish: `revalidateTag('report:{public_id}', { expire: 0 })` (publish too, so a republish never serves a cached 404). Takedown: `revalidateTag('user:{username}', { expire: 0 })`. No `updateTag` (Server Actions only). Confirmed vs `revalidateTag.md`: 2-arg form current, 1-arg deprecated.
10. CDN lag: confirmed (`cdn-caching.md:26`) `revalidateTag` doesn't purge CDN copies → `/report/*` and `/api/og/*` use `s-maxage` ≤ 60 + SWR; visibility changes land within ~1 min. TODO: check if Vercel purges CDN on tag expiry; if so, raise `s-maxage`.
11. OG: `/api/og/[public_id]`, 404 unless public. Per-audit URL, so X's unpurgeable preview cache never shows the wrong report.
12. LLM: Claude Haiku (`claude-haiku-5-5`), Vercel AI SDK structured output + Zod, temp 0; output cached by `snapshot_hash` + `rubric_version` + `model`. Verify on Day 2, before code depends on it: `generateObject` vs `generateText` + `Output.object` in the installed SDK; Haiku 5.5 accepts temp 0.
13. Lift estimates: computed in code by earnings model. LLM writes rewrites/reasons only, never dollar figures.
14. Fetching: UA `StoreDoctor/0.1 (+<site url>)`; only the requested page. Fetch cache = latest row's `snapshot` with `snapshot_fetched_at` < 24 h (Postgres only). Re-run uses the cache too, so at most one fetch per username per 24 h (#24).
15. Cost guards: Upstash Ratelimit per IP (audit, re-run). Global daily LLM cap (Upstash counter), incremented only on actual LLM calls; reused results (copies, followers) still served over cap. Shortcut: check-before/count-after can overshoot under concurrency → mark `// shortcut:`; fix if needed: `INCR` before call, refund on failure.
16. Stuck runs: write side: inline sweep in `POST /api/audit` fails runners > 2 min + their followers. Read side: `/r/[id]` and follower poll treat pending > 2 min as failed (no write). No cron for this.
17. Usernames: trimmed + lowercased on input, stored and compared lowercase everywhere (block list, fetch cache, dedupe, `/report` match). Non-canonical `/report/[username]/...` → 308 to lowercase. Day 2: confirm Stan resolves usernames case-insensitively.
18. Validation order: normalize → regex → block list → fetch/cache → insert runner. 404/blocked → no row.
19. Admin takedown: `POST /api/admin/takedown {username, reason}` (`ADMIN_TOKEN`): insert into `blocked_usernames`, then delete every audit row for the username (#24), expire `user:{username}`. Public reads also check the block list, so a publish that races the takedown still 404s. An audit that passed the block check before the takedown can insert a row after the `DELETE`; it stays unreadable publicly, and re-running the fallback `DELETE` removes it. Unblock: SQL only.
20. No ID leaks: private `id` and `source_audit_id` never in public pages, metadata, images, API responses or our analytics. `/r/*`: `Referrer-Policy: no-referrer` header + `rel="noreferrer"` on outbound links; excluded from Vercel Analytics (or path redacted in `beforeSend`). `/r/[id]` never reveals the followed/copied source. Accepted risk: Vercel request logs record `/r/[id]` paths; only project owners can read them.
21. Parser: TS bracket matcher (string/escape-aware) replaces Python `JSON.raw_decode`; Zod-validate `storeData`/`user` before whitelisting into `StoreSnapshot`; daily canary cron.
22. Tooling: pnpm, Vitest, GitHub → Vercel preview deploys.
23. Sharing: v1 never includes the creator's `@handle`: not in share text or the X intent URL, not in OG/Twitter meta (`twitter:creator` is never the creator), not on the card image. The plain username in the URL is fine (no `@`, no notification). Revisit only if owner verification ships.
24. Retention:
    - Raw profile fields (full_name, user_image, bio, socials) live under `snapshot.profile`, kept 24 h as fetch cache. Daily `GET /api/cron/purge`: `UPDATE audits SET snapshot = snapshot - 'profile' WHERE snapshot ? 'profile' AND snapshot_fetched_at < now() - '24 hours'`. Daily schedule → actually held 24–48 h. Reports render from `result` + `username`, never `snapshot.profile`.
    - Score + derived findings (`result`, may quote the bio) kept until takedown, which deletes the rows (#19).
    - Re-runs inside 24 h reuse the cached snapshot (#14) → no new fetch, no new data point. This is what makes "no saved history in v1" true.

## Schema
```
audits(
  id                  uuid primary key default gen_random_uuid(),      -- PRIVATE: /r/[id]
  public_id           uuid not null unique default gen_random_uuid(),  -- PUBLIC: /report/.../[public_id], /api/og/[public_id]
  username            text not null check (username = lower(username)),
  status              text not null default 'pending',   -- pending | complete | failed
  source_audit_id     uuid references audits(id),        -- null = runner; set = follower or copied result
  snapshot            jsonb,                             -- whitelisted StoreSnapshot only; .profile purged after 24 h (#24)
  snapshot_hash       text,
  snapshot_fetched_at timestamptz,                       -- when this snapshot was actually fetched from Stan
  result jsonb, error text, rubric_version text not null, model text not null,
  llm_called          boolean not null default false,    -- true only when this row paid for LLM work
  created_at timestamptz not null default now(), completed_at timestamptz,
  published_at        timestamptz                        -- non-null = public; the only visibility field
)
index (username, snapshot_fetched_at desc)                                         -- fetch cache
index (username, created_at desc) where status = 'pending'                         -- sweep, follow lookup
index (username, snapshot_hash, rubric_version, model) where status = 'complete'  -- result reuse
index (source_audit_id) where status = 'pending'                                   -- fan-out to followers
unique index one_runner_per_content (username, snapshot_hash)
  where status = 'pending' and source_audit_id is null                             -- one runner per store content
blocked_usernames(username text primary key check (username = lower(username)), reason text,
                  created_at timestamptz not null default now())
```

## Request flow: `POST /api/audit {username}`; Re-run = same request
```
1. rate limit (per IP)
2. u = lower(trim(username)); bad format → 400; u in blocked_usernames → 403, no row
3. sweep: WITH swept AS (UPDATE audits SET status='failed', error='timeout' WHERE username=u AND status='pending'
            AND source_audit_id IS NULL AND created_at < now() - '2 min' RETURNING id)
          UPDATE audits SET status='failed', error='timeout' WHERE status='pending' AND source_audit_id IN (SELECT id FROM swept)
4. pending runner exists for u? → insert follower (newest runner), go to 9   -- no fetch
5. snapshot = (latest row with snapshot_fetched_at < 24 h) ?? fetch()
   404 → return 404, no row; snapshot_fetched_at = time of the actual fetch (copied when cached)
6. complete match (snapshot_hash, rubric_version, model)? → insert complete row, result copied,
   source_audit_id = match; stream {auditId: id}, {done}
7. (removed in r8: fresh-fetch follow)
8. daily LLM cap reached? → pending runner for (u, snapshot_hash)? insert follower, go to 9; else refuse (no row)
   INSERT runner ... ON CONFLICT (username, snapshot_hash) WHERE status='pending' AND source_audit_id IS NULL
   DO NOTHING → no row inserted? insert follower instead, go to 9
   else: stream {auditId: id}; rules ∥ LLM (increment cap, llm_called = true); score; save:
     UPDATE audits SET status='complete', result=$r, completed_at=now() WHERE id=$runner AND status='pending'
     0 rows → swept meanwhile: mark its pending followers failed (catches ones attached after the sweep; one attached after this stays pending, read as failed at 2 min), stop
   fan out: UPDATE audits SET status='complete', result=$r, snapshot=$s, snapshot_hash=$h,
              snapshot_fetched_at=$t, completed_at=now() WHERE source_audit_id=$runner AND status='pending'
   runner error: mark runner + its pending followers failed (same status='pending' guard)
9. follower: stream {auditId: id}; poll own row ~500 ms until complete/failed; pending > 2 min = failed
```

## Routes
```
GET  /r/[id]                         → private report or progress/failure; pending > 2 min = failed;
                                       no-store, noindex, Referrer-Policy: no-referrer; no analytics
POST /api/audit/[id]/publish         → one UPDATE: published_at=now() WHERE id=$1 AND status='complete' AND NOT EXISTS (blocked u);
                                       0 rows → look up why: blocked → 403, else 409; expire report:{public_id}; returns share URL
POST /api/audit/[id]/unpublish       → published_at=NULL; expire report:{public_id}
GET  /report/[username]/[public_id]  → non-lowercase username → 308; published_at IS NOT NULL + username match + not blocked, else 404;
                                       tags report:{public_id}, user:{username}; s-maxage ≤ 60; noindex
GET  /api/og/[public_id]             → 1200×630 card, 404 unless published_at IS NOT NULL and username not blocked; same tags; s-maxage ≤ 60
POST /api/admin/takedown             → ADMIN_TOKEN; block username, delete all its audits, expire user:{username}
GET  /api/cron/canary                → daily parse of a known store; alert on failure
GET  /api/cron/purge                 → daily; strip snapshot.profile older than 24 h (#24)
```

```sql
-- Takedown fallback. Then expire user:{username} (or redeploy); SQL alone leaves cached copies until s-maxage.
INSERT INTO blocked_usernames (username, reason) VALUES (lower('<username>'), '<reason>') ON CONFLICT (username) DO NOTHING;
DELETE FROM audits WHERE username = lower('<username>');  -- one statement, so self-referencing source_audit_id rows go together
-- Unblock (deleted audits don't come back): first re-run the DELETE above (catches in-flight inserts), then:
DELETE FROM blocked_usernames WHERE username = lower('<username>');
```

## Revisit when
- Timeouts/failed saves → Inngest (#4); followers wait on the job.
- Followers lag runners → stream runner events to followers (needs shared progress store).
- Creators want a "latest" link → `/report/[username]` 302 to newest pinned report, only after ownership verification.
- Creators claim reports → verification (code in Stan bio); drop visitor label (#8); only then consider `@handle` in owner shares (#23).
- Vercel purges CDN on tag expiry → raise `s-maxage` (#10). Stan usernames case-sensitive → revisit #17.
- Honest UA blocked → stop and decide; don't silently revert (#14).

## Spike result (Nov 16): PASS
- `stan.store/<username>`: server-rendered Next.js App Router; data in RSC flight payload (`self.__next_f.push([1,"..."])`) as plain JSON.
- Extract: concat + JSON-unescape chunks; decode objects at `{"storeData":` (store + `pages[]`) and `"user":{` (username, full_name, bio, user_image, data.socials).
- Page fields: `type` (`link`, `course`, `digital-download`, `meeting`, …), `order`, `status`, `data.product` {title, description, image, price.amount, reviews[]}, `data.button` {title, tagline, button_text, layout}.
- Unknown username → 404. Homepage = separate Vue SPA; ignore. Plain `fetch` suffices; no Playwright/cheerio. Spike used browser UA; honest UA unverified.
- Raw `user` includes payment/Stripe fields (`pk_live`, connected payment methods) → whitelist into `StoreSnapshot`; never persist raw blob.
- Fixtures: `fixtures/stores/{LovedByCreators,stanforcreators,stan}.html` (links-only, mixed course/download, near-empty).
- Risk: Stan's RSC shape can change without notice → adapter, fixtures, Zod, canary.
